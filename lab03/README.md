* **Сильная типизация** -  язык программирования содержит большое число правил неявного преобразования типа, допускает каламбуры типизации.
* **Слабая типизация** - язык программирования не содержит (почти не содержит) правил неявного преобразования типа.

### Задание 2 **(3)**
*Запишите правила неявного преобразования типов в языке С++*

- Существуют неявные преобразования между всеми базовыми типами.
- Преобразование в bool: 0 — false; остальные значения — true.
- Преобразование из bool: false — 0; true — 1.
- Преобразование из вещественных в целочисленные: отсечение дробной части.
- Преобразование с символьными типами: по коду символа.
- При присваивании значение правого операнда приводится к типу левого операнда.
- При вызове функции фактический параметр приводится к типу формального параметра.
- Результат условного выражения в инструкциях ветвления и цикла приводится к логическому типу.
- Если оператор требует целого числа то операнд приводится к целому (суффиксный инкремент, декремент, сдвиги, остатки от деления, битовые операции).
- Если оператор требует логического значения, то операнды приводятся к логическому типу (логические операции).
- Если длины обоих типов меньше int то преобразование к int.
- Если типы разной длины, то преобразуется меньший к большему.
- Если типы равной длины и один знаковый, а другой беззнаковый, то знаковый приводится к беззнаковому.
- Если один целый, а другой вещественный, то целый приводится к вещественному.

#### Пример 1 - `int` в `bool`

**C++:**
```cpp
#include <iostream>

int main() {
    int n = 42;
    bool flag = n;
    std::cout << flag << '\n';
    return 0;
}
```

Программа компилируется: ненулевое `int` неявно преобразуется в `true`.

**Java:**
```java
public class Main {
    public static void main(String[] args) {
        int n = 42;
        boolean flag = n; // ошибка
    }
}
```

В Java `int` нельзя неявно преобразовать в `boolean`.

#### Пример 2 - `int` в `char`

**C++:**
```cpp
#include <iostream>

int main() {
    int n = 65;
    char c = n;
    std::cout << c << '\n';

    return 0;
}
```

C++ допускает неявное преобразование `int` в `char`.

**Java:**
```java
public class Main1 {
    public static void main(String[] args) {
        int n = 65;
        char c = n; // ошибка
    }
}
```

В Java для переменной типа `int` требуется явное преобразование: `char c = (char)n;`

#### Переменная `a` (`x & y`):
Оператор `&` — это **побитовое И**.

* В языке C++ побитовые операции не предназначены для работы с логическим типом `bool` напрямую.
* Перед выполнением операции срабатывает механизм **целочисленного повышения (integral promotion)**. Компилятор неявно преобразует оба операнда (`x` и `y`) из типа `bool` в тип `int` (значение `true` становится `1`, а `false` — `0`).
* Так как операция выполняется над двумя целыми числами (`int & int`), её результат также имеет тип `int`.
* Ключевое слово `auto` анализирует тип возвращаемого значения и выводит `int`.

#### 2. Переменная `b` (оператор `&&`)

Оператор `&&` — это **логическое И**.

* В отличие от побитовых, логические операторы (`&&`, `||`, `!`) в C++ жестко привязаны к работе с булевой логикой.
* Согласно стандарту C++, результатом любой логической операции **всегда** является тип `bool` (значение `true` или `false`), независимо от того, какие типы имели исходные операнды до целочисленного повышения.
* Ключевое слово `auto` анализирует тип возвращаемого значения и выводит `bool`.

### Задание 5. **(2)**

*Приведите разумные (логичные) примеры использования в 
С++ ключевых слов* **typedef, auto, decltype, static_cast** и оператора **sizeof**.

*Записанные программы сохраните в папке с номером задания. В отчет запишите пояснения к программам*.

#### Пояснения к программе

##### 1. Ключевое слово `typedef`
**Пример:** `typedef double real;`
**Пояснение:** Создает удобный псевдоним для существующего типа. Теперь слово `real` означает тип `double`.

##### 2. Ключевое слово `auto`
**Пример:** `auto a = 3.14;`
**Пояснение:** Компилятор автоматически определяет тип переменной `a` на основе присвоенного значения (в данном случае `double`).

##### 3. Ключевое слово `decltype`
**Пример:** `decltype(a) b = a;`
**Пояснение:** Определяет тип переменной `b` на основе типа уже существующего выражения или переменной `a`.

##### 4. Оператор `sizeof`
**Пример:** `sizeof(int)`
**Пояснение:** Возвращает размер указанного типа или переменной в байтах на этапе компиляции.

##### 5. Оператор `static_cast`
**Пример:** `static_cast<int>(a)`
**Пояснение:** Выполняет явное и безопасное приведение типов. В примере дробное число `double` принудительно преобразуется в целое `int` с отбрасыванием дробной части.

### Задание 6 **(2)**

Рассмотрите следующий фрагмент программы. 
```
int a = -1, b = 1;
unsigned int c = 1;
std::cout << a*b << std::endl;
std::cout << a*c << std::endl;
```
* *Объясните работу этой программы, используя правила неявного преобразования типов*
* *Что произойдет, если тип* **int** *заменить на* **short**, а **unsigned int** на **unsigned short**?*

1. Первое выражение: `a * b`

Обе переменные имеют тип `int`, поэтому дополнительного преобразования не происходит: `-1 * 1 = -1`

2. Второе выражение: `a * c`

Здесь участвуют `int` и `unsigned int` одинакового размера. Знаковый `int` приводится к `unsigned int`.

Поэтому `-1` превращается в максимальное значение `unsigned int`. Для 32-битного `unsigned int` это: `2^32 - 1 = 4294967295`

и результат: `4294967295 * 1 = 4294967295`

3. Если заменить типы на `short` и `unsigned short`

```cpp
short a = -1, b = 1;
unsigned short c = 1;
```

При арифметической операции оба типа сначала продвигаются до `int`, поскольку их диапазоны помещаются в `int` на обычной реализации C++.

Поэтому:

```cpp
a * b  // int: -1
a * c  // int: -1
```

Результаты будут:

```
-1
-1
```

Именно целочисленное продвижение до `int` не дает `-1` превратиться в `unsigned short`.


### Задание 7 **(2)**
*Рассмотрите следующий фрагмент программы.*
```
int x = 7, y = 4;
long double d = 0.25;
cout << (x / y) / d << endl;
cout << (x / d) / y << endl;
long a = 200000, b = 200000;
long long c = 200000;
std::cout << (a * b) * c << std::endl;
std::cout << a * (b * c) << std::endl;
```
*Почему изменения порядка действий приводит
к изменению результата? Объясните работу этой программы, используя правила неявного преобразования типов*

**Первая пара выражений**:

```cpp
int x = 7, y = 4;
long double d = 0.25;

std::cout << (x / y) / d << std::endl;
std::cout << (x / d) / y << std::endl;
```

1. В первом выражении сначала выполняется: `x / y`

Оба операнда имеют тип `int`, поэтому выполняется целочисленное деление: `7 / 4 = 1`

Затем: `1 / 0.25 = 4`

Результат — `4`.

2. Во втором выражении сначала вычисляется: `x / d`

`x` автоматически преобразуется в `long double`: `7 / 0.25 = 28`

После этого: `28 / 4 = 7`

Результат — `7`.

Следовательно, порядок действий влияет на момент преобразования типов: в первом случае дробная часть теряется еще при `7 / 4`, во втором — деление сразу происходит в `long double`.

**Вторая пара выражений**:

```cpp
long a = 200000, b = 200000;
long long c = 200000;

std::cout << (a * b) * c << std::endl;
std::cout << a * (b * c) << std::endl;
```

Здесь результат зависит от размера типа `long` на конкретной платформе.

Если `long` — 32-битный:

`a * b` сначала вычисляется как `long`: `200000 * 200000 = 40 000 000 000`

Это больше максимального значения 32-битного `long`, поэтому происходит переполнение уже на первом умножении. После этого полученное значение участвует в умножении на `long long`.

Во втором варианте:

`b * c` сразу выполняется как `long long`, поэтому переполнения `long` нет. Затем `a` также приводится к `long long`, и вычисляется произведение в более широком типе.

Если же `long` на платформе 64-битный, переполнения нет и оба выражения дадут одинаковый результат: `8 000 000 000 000 000`

Поэтому при запуске на 64-битной Linux/macOS-платформе различия во второй паре может не быть (как, например, у меня и произошло). Это не противоречит правилам: оно зависит от фактической разрядности `long`.
